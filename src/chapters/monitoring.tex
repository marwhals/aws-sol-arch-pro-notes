\section{CloudWatch}

\subsection{CloudWatch Metrics}
\begin{itemize}
    \item Provided by many AWS services
    \item EC2 standard: 5 minute, detailed monitoring: 1 minute
    \item EC2 RAM is not a built-in metric
    \item Can create customer metrics: standard resolution 1 minute, high resolution 1 sec
\end{itemize}

\subsection{CloudWatch Alarms}
\begin{itemize}
    \item Can trigger actions: EC2 action (reboot, stop, terminate, recover), Auto Scaling, SNS
    \item Alarm events can be intercepted by Amazon EventBridge
\end{itemize}

\subsection{CloudWatch Dashboards}
\begin{itemize}
    \item Display metrics and alarms
    \item Can show metrics of multiple regions
\end{itemize}

\subsection{CloudWatch Syntethics Canary}
%TODO add diagram
\begin{itemize}
    \item Configurable script that monitors your APIs, URL, Websites,......
    \item Reproduce what your customers do programmatically to find issues before customers are impacted
    \item Check the availability and latency of your endpoints and can store load time data and screen shots of the UI
    \item Integration with CloudWatch Alarms
    \item Scripts written in Node.js or Python
    \item Programmatic access to a headless Google Chrome browser
    \item Can run once or on a regular schedule
\end{itemize}

\subsection{CloudWatch Synthetics Canary Blueprints}
\begin{itemize}
    \item Heartbeat Monitor - load URL, store screenshot and an HTTP archive files
    \item API Canary - test basic read and write functions of REST APIs
    \item Broken Link Checker - check all links inside the URL that you are testing
    \item Visual Monitoring - compare a screenshot taken during a canary run with a baseline screen shot
    \item Canary Recorder - used with CloudWatch Synthetics Recorder (record your actions on a website and automatically generates a script for that)
    \item GUI Workflow Builder - verifies that action can be taken on your webpage (e.g test a webpage with a login form)
\end{itemize}


\section{CloudWatch Logs}

\subsection{AWS Cloudwatch Logs - Sources}
\begin{itemize}
    \item SDK, CloudWatch Logs Agent, CloudWatch Unified Agent
    \item Elastic Beanstalk: collection of logs from application
    \item ECS: collection from containers
    \item AWS Lambda: Collection from function logs
    \item VPC Flow Logs: VPC specific logs
    \item API Gateway
    \item CloudTrail based on filter
    \item CloudWatch log agents: for examples on EC2 machines
    \item Route53: Log DNS queries
\end{itemize}

\subsection{CloudWatch Logs}
\begin{itemize}
    \item Log groups: arbitrary name, usually representing an application
    \item Log stream: instances within application / log files / containers
    \item Can define log expiration policies (never expire, 30 days, etc.......)
    \item Optional KMS encryption
    \item CloudWatch Logs can send logs to:
    \begin{itemize}
        \item Amazon S3 (exports)
        \item Kinesis Data Streams
        \item Kinesis Data Firehose
        \item AWS Lambda
        \item ElasticSearch
    \end{itemize}
\end{itemize}

\subsection{CloudWatch Logs Metric Filter and Insights}
\begin{itemize}
    \item CloudWatch Logs can use filter expressions
    \item For example, find a specific IP inside of a log
    \item Or count occurrences of "ERROR" in your logs
    \item Metric filters can be used to trigger alarms
\end{itemize}

z CloudWatch Logs Insights can be used to query logs and add queries to CloudWatch Dashboards

\subsection{CloudWatch Logs - S3 Export}
\begin{itemize}
    \item S3 buckets must be encrypted with AES-256 (SSE-S3) or SSE-KMS
    \item Log data can take up to 12 hours to become available for export
    \item The API call is CreateExportTask
    \item Not near-real time or real-time..... use Logs Subscriptions instead
\end{itemize}

    \item Schedule: Cron jobs (scheduled scripts)
    \item Event pattern: Event rules to react to a service doing something
    \item Trigger Lambda functions, send SQS/ SNS messages
\end{itemize}

\subsection{Amazon EventBridge}
%TODO add diagrams
\begin{itemize}
    \item Event buses can be accessed by other AWS accounts using Resource-based Policies
    \item You can archive events (all/filter) sent to an event bus (indefinitely or set period)
    \item Ability to replay archived events
\end{itemize}

\subsection{Amazon EventBridge - Schema Registry}
\begin{itemize}
    \item EventBridge can analyse the events in your bus and infer the schema
    \item The Schema Registry allows you to generate code for you application, that will know in advance how data is structured in the event bus
    \item Schema can be versioned
\end{itemize}

\subsection{Amazon EventBridge - Resource-based Policy}
%TODO add diagram and JSON
\begin{itemize}
    \item Manage permissions for specific Event Bus
    \item Example: allow/deny events from another AWS account or AWS region
    \item Use case: aggregate all events from your AWS Organisation in a single AWS account or AWS region
\end{itemize}

\begin{itemize}

\section{AWS Personal Health Dashboard}
\begin{itemize}
    \item Global service
    \item Show how AWS outages directly impact you
    \item Show the impact on your resources
    \item List issues and actions you can do to remediate them
    \item Will show \textbf{maintenance} events from AWS
    \item Programmatically accessible through the AWS Health API
    \item Aggregations across multiple accounts of an AWS Organisation
    \item https://phd.aws.amazon.com/
\end{itemize}

\subsection{Health Event Notifications}
%TODO add diagram
\begin{itemize}
    \item Use EventBridge (CloudWatch events) to react to changes for AWS Health events in your AWS account
    \item Examples: receive email notifications when EC2 instances in your AWS account are scheduled for updates
    \item Can't be used to return public events from the Service Health Dashboard
    \item Use cases: send notifications, capture event information, take corrective action,..........
\end{itemize}
